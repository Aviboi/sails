# Fluent 2D section study: fully scripted workflow

Files in this folder come from `4_Section_Design.ipynb` Section 8d (regenerated on every run):
`section_f06.0pct` … `section_f10.0pct` (+ `section_f08.0pct_spine`) as `.csv` and `.txt` (metres, chord 0.65 m, LE at x = 0, pivot at x = 0.325 m), and `run_matrix.csv` (camber × Re × angle).

Scripts (not regenerated by the notebook):

| Script | Job | Status |
|---|---|---|
| `make_mesh.py` | section CSV → gmsh mesh (boundary-layer quads + triangles) → native Fluent `.msh` with zones wall / inlet / outlet | **Tested** here: all six sections mesh in about 30 s each; independent check passes |
| `check_msh.py` | reads a `.msh` back and checks orientation, closure, areas, angles | **Tested** |
| `build_case.py` | PyFluent: read mesh, Transition SST, inlet turbulence, schemes, reports, initialise, save `.cas.h5` | **Run against Fluent 26.1 Student (PyFluent 0.43): all 15 steps ok.** Every step is logged and a failure does not stop the rest |
| `run_fluent_sweep.py` | PyFluent: angle sweep from `run_matrix.csv`, writes `results.csv` | **Not run against Fluent**; setting names checked, matrix, rotation and resume logic tested |
| `verify_api.py` | checks the settings paths the two PyFluent scripts use against the generated API of your installed `ansys-fluent-core` (no Fluent needed) | **Tested** |

## Setup (once)
Use a virtual environment (on Windows PowerShell):
```
python -m venv fluentvenv
.\fluentvenv\Scripts\Activate.ps1
pip install gmsh numpy ansys-fluent-core     # use Python 3.13 or older (3.14 is the system default here)
python verify_api.py        # no Fluent needed; every line should say ok for your Fluent version
```
`ansys-fluent-core` needs a Fluent installation and licence, and its version must match your Fluent. gmsh is needed only for `make_mesh.py` (4.11 or newer).

## Workflow
```
# 1. mesh (30 s). Writes f08.msh and f08_mesh_report.txt
python make_mesh.py --section section_f08.0pct.csv --out f08.msh
python check_msh.py f08.msh                       # expect RESULT: OK

# 2. build the case (one per camber per turbulence intensity)
python build_case.py --mesh f08.msh --out f08_tu0.1.cas.h5 --tu 0.1
python build_case.py --mesh f08.msh --out f08_tu0.5.cas.h5 --tu 0.5

# 3. first real run: ONE angle, check the printed RAW compute() output and the numbers against NeuralFoil
python run_fluent_sweep.py --matrix run_matrix.csv --case f08_tu0.1.cas.h5 --camber 8 --wind "8 kn" --alphas 4 --max-cases 1 --tag tu0.1 --out results.csv

# 4. the priority-1 set (8 % camber, two wind speeds, all angles)
python run_fluent_sweep.py --matrix run_matrix.csv --case f08_tu0.1.cas.h5 --camber 8 --wind "8 kn"  --priority 1 --tag tu0.1 --out results.csv
python run_fluent_sweep.py --matrix run_matrix.csv --case f08_tu0.1.cas.h5 --camber 8 --wind "27 kn" --priority 1 --tag tu0.1 --out results.csv
```
Use `--dry-run` on the sweep to list cases without starting Fluent, `--check-only` on `build_case.py` to read the mesh and run Fluent's mesh check only, and `--tui-extra FILE` to apply any setting the API refuses as raw TUI text.

## What the mesh is
- Domain: rectangle from −20 c to +30 c in x and y around the section (LE at the origin). `inlet` = left + bottom edges, `outlet` = top + right edges. Valid for angles of attack 0–30° (free stream runs up and to the right).
- About 118k cells: 45 rows of boundary-layer quads (first cell 0.020 mm, growth 1.12, about 30 mm thick), then triangles; edges refined from curvature (smallest element 0.3 mm), wake box at 15 mm.
- One mesh serves every wind speed and angle. The first cell is sized for 27 kn (y⁺ ≈ 1 there, lower at lower speeds). The angle is set by rotating the inflow, never the geometry.
- Mesh quality from the tested run (8 %): all cell areas positive, minimum interior angle about 24°, every cell closes.
- Fluent mesh-file conventions used: c0 is the cell on the **left** of the directed face n0→n1, c1 on the right. Confirmed by reading the f08 mesh into Fluent 26.1 (the opposite convention gave all-negative volumes). This is the default; `--no-flip-faces` gives the other one.

## Physics set by `build_case.py`
Pressure-based steady incompressible air (Fluent defaults: 1.225 kg/m³, 1.7894e-5 Pa·s), Transition SST, coupled scheme, second-order upwind; inlet by velocity components, turbulence intensity 0.1 % (about Ncrit 8) or 0.5 % (about Ncrit 4) from the Mack relation, turbulent viscosity ratio 5; pressure outlet at 0 gauge. The script prints the inlet state and air properties so you can confirm them, and lists every step that failed.

## Output of the sweep (`results.csv`)
`tag, camber_pct, wind, Re, alpha_deg, V_mps, Fx_N, Fy_N, Mz_Nm, CL, CD, Cm_pivot, iterations, converged, seconds`

Forces are per metre of depth. L = −Fx sin α + Fy cos α, D = Fx cos α + Fy sin α, CL = L/(q c), CD = D/(q c), Cm_pivot = Mz/(q c²) with q = ½ρV², c = 0.65 m; moment about (0.325, 0), nose-up positive (the notebook's S13 convention). Restarting skips finished cases for the same `--tag`; each angle continues from the previous solution (`--reinit` forces a fresh start). Convergence means CL and Cm each change by less than `--tol` (0.002) over `--chunk` iterations; residuals are not checked by the script.

## Checks before trusting any camber trend
y⁺ ≲ 1 on the wall (confirm in Fluent); three-mesh independence on 8 % at α = 6° and 12° (coarsen/refine with `--hs`, `--y1`, `--curv-n`); a larger domain at one angle (`--far`, `--far-down`); NeuralFoil comparison at the same Re and Ncrit. Steady results above stall are not reliable: use transient runs there (not scripted yet).

## What was verified without Fluent
`verify_api.py` found every settings path used by the scripts in PyFluent 0.43's generated API for Fluent 24.2, 25.1, 25.2 and 26.1 (24.2 keeps the discretisation scheme directly under `methods`; the script handles both). In 27.1 `setup.models.viscous` moved under `setup.models.turbulence` but the old path remains as an alias. This checks names only, not allowed string values (for example the exact turbulence-specification text), the `compute()` return format, or behaviour.

## If a Fluent call fails
`build_case.py` and the sweep touch these settings-API paths; fix them to your version using the PyFluent documentation:
`settings.file.read_mesh / read_case / write_case`, `settings.setup.models.viscous.model`, `settings.setup.boundary_conditions.velocity_inlet[...]` (`momentum.velocity_specification_method`, `momentum.velocity_components`, `turbulence.*`), `settings.solution.methods.p_v_coupling.flow_scheme`, `settings.solution.methods.spatial_discretization.discretization_scheme`, `settings.solution.report_definitions.force / moment / compute`, `settings.solution.initialization.hybrid_initialize`, `settings.solution.run_calculation.iterate`.
The return format of `compute()` is not documented; the sweep prints the raw output once and reads the numbers in order (fx, fy, mz).
